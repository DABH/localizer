## One line of code

<Tabs syncKey="lang">
<TabItem label="Go">
```go title="main.go" ins={2}
root := newRootCmd()
localizer.Localize(root, locales.FS)
if err := root.Execute(); err != nil {
	os.Exit(1)
}
```
</TabItem>
<TabItem label="Python">
```python title="yourcli/__main__.py" ins={1}
localizer.localize(app, "yourcli.locales")
app()
```
</TabItem>
</Tabs>

## Why Localizer

<CardGrid>
	<Card title="Everything your CLI says" icon="comment-alt">
		Command descriptions, flag help, usage text, your framework’s built-in commands and the errors it
		prints — Cobra, Typer, Click or argparse — are translated automatically. Your own messages go through a
		few helpers at your output chokepoints.
	</Card>
	<Card title="No runtime cost" icon="rocket">
		Catalogs are compiled in with `go:embed` or shipped inside your Python package. Nothing is downloaded
		and nothing is reported. English output is unchanged, and other languages add a few milliseconds.
	</Card>
	<Card title="Always in sync" icon="code-branch">
		When a push adds or changes strings, Localizer translates just those and updates one pull request.
		Strings you delete are removed from the catalogs, with a guard against dropping too many at once.
	</Card>
	<Card title="Safe by design" icon="approve-check">
		Every translation is checked twice, by the service and again at runtime. Placeholders, flags and code
		spans must survive intact, and text that matches no catalog entry passes through unchanged.
	</Card>
	<Card title="Human edits win" icon="pencil">
		Translations are plain JSON in your repository. Correct any entry, and Localizer keeps your version;
		only an entry that fails validation is replaced.
	</Card>
	<Card title="No keys to leak" icon="padlock">
		You authenticate through the GitHub App or your workflow’s short-lived OIDC token, so there is no
		secret to store. Localizer serves open-source repositories only.
	</Card>
</CardGrid>

## How it works

<Steps>

1. **Connect your repository.** Add the [GitHub Action](guides/github-action/) to a workflow or install
   the [GitHub App](guides/github-app/).

2. **Merge the onboarding pull request.** It adds `.localizer.yml`, a locales package with one catalog per
   language, and the one-line integration.

3. **Keep shipping.** When your strings change, the translations pull request updates itself. Review it
   and merge it like any other change.

4. **Your users see their language.** Localizer reads their environment and OS settings, and falls back to
   English.

</Steps>
