---
title: Getting started
description: Add Localizer to a Go or Python CLI and get its first translations.
---

import { Steps, Tabs, TabItem } from '@astrojs/starlight/components';

Localizer works with Go and Python CLIs in public GitHub repositories. For a
[Cobra](https://github.com/spf13/cobra) (v1.8 or later), [kong](https://github.com/alecthomas/kong) or
[urfave/cli](https://cli.urfave.org/) v3 CLI, or a [Typer](https://typer.tiangolo.com/),
[Click](https://click.palletsprojects.com/) or argparse CLI (Python 3.10 or later), one line translates the
whole command tree. Other CLIs call `Init`/`init` and use the
[output helpers](../guides/integration/#2-your-own-messages).

:::note[Subscription]
The hosted translation service needs a subscription for the GitHub account that owns the repository: see
[Pricing](/pricing/).
:::

:::tip[Using a coding agent?]
Point it at [AGENTS.md](https://locale.dev/AGENTS.md); see [Using a coding agent](../agents/).
:::

<Steps>

1. **Connect your repository.**

   <Tabs>
   <TabItem label="GitHub Action">
   Add `.github/workflows/localizer.yml`:

   ```yaml
   name: Localizer
   on:
     push:
       branches: [main] # your default branch
     workflow_dispatch:

   permissions:
     contents: write
     pull-requests: write
     id-token: write

   concurrency:
     group: localizer # one run at a time: a second push waits
     cancel-in-progress: false

   jobs:
     translations:
       runs-on: ubuntu-latest
       steps:
         - uses: actions/checkout@v7
         - uses: DABH/localizer/action@v0.6.0
   ```

   Then turn on **Settings → Actions → General → Allow GitHub Actions to create and approve pull
   requests**, and push. See the [GitHub Action guide](../guides/github-action/).
   </TabItem>
   <TabItem label="GitHub App">
   [Install the Localizer GitHub App](https://github.com/apps/localedev/installations/new) (called
   **localedev** on GitHub) on the repository. Nothing else is needed. See the
   [GitHub App guide](../guides/github-app/).
   </TabItem>
   </Tabs>

2. **Merge the onboarding pull request.** The first run opens **Localize this CLI with Localizer**, which
   adds `.localizer.yml` with the default settings ([configuration](../reference/configuration/)), the
   locales package with one catalog per language, and the one-line integration when Localizer finds exactly
   one place where your CLI runs. Otherwise the pull request tells you where to add it.

   <Tabs syncKey="lang">
   <TabItem label="Go">
   - `locales/embed.go` and `locales/ja.json`, `locales/de.json`, …;
   - `localizer.Localize(root, locales.FS)` right before `root.Execute()`, and the module in `go.mod`.
   </TabItem>
   <TabItem label="Python">
   - `yourcli/locales/__init__.py` and `yourcli/locales/ja.json`, `yourcli/locales/de.json`, … inside your
     package (with `src/` layouts too);
   - `localizer.localize(app, "yourcli.locales")` right before the app runs, and `localizer` in
     `pyproject.toml`’s dependencies. Regenerate your lock file if you keep one, and with setuptools make
     sure the JSON files are packaged (`[tool.setuptools.package-data]`).
   </TabItem>
   </Tabs>

3. **Try it.**

   <Tabs syncKey="lang">
   <TabItem label="Go">
   ```sh
   go build -o yourcli .
   LANG=ja_JP.UTF-8 ./yourcli --help
   LOCALIZER_LANG=de ./yourcli --help
   LOCALIZER_LANG=qps ./yourcli --help   # pseudo-localization: shows every string Localizer handles
   ```
   </TabItem>
   <TabItem label="Python">
   ```sh
   pip install -e .                      # or: uv sync
   LANG=ja_JP.UTF-8 yourcli --help
   LOCALIZER_LANG=de yourcli --help
   LOCALIZER_LANG=qps yourcli --help     # pseudo-localization: shows every string Localizer handles
   ```
   </TabItem>
   </Tabs>

4. **Hook your own messages.** Help and your framework’s errors are covered by the one line. For messages
   your code prints, wrap your output helpers with `localizer.T`, `localizer.Sprintf`, `localizer.Error` or
   `localizer.Writer` (Go), or `localizer.t`, `localizer.tf` and `localizer.error` (Python). The
   [integration guide](../guides/integration/) shows how.

5. **Keep tests in English.** Set `LOCALIZER_LANG=en` wherever output is compared with golden files (for
   pytest, a `pytest_configure` hook in the root `conftest.py`). See [Testing](../guides/testing/).

</Steps>

From now on, every push that changes user-facing strings updates the **Update translations** pull request.
